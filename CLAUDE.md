## Project: RadarMoto

Cross-platform (iOS + Android) app for motorcyclists that detects speed cameras via GPS and alerts with vibration, a single voice announcement and a lock-screen notification. Works in the background with the screen off. Built with **React Native + Expo (SDK 58) + TypeScript**, one codebase for both stores.

The original native Swift app lives in `legacy-ios/` as reference only (XcodeGen project; not built from this branch). Delete it once the RN app reaches parity on-road.

## Commands

```bash
npm test                 # Jest unit tests (pure logic in src/core, src/data)
npm run typecheck        # tsc --noEmit
npx expo-doctor          # dependency/config sanity check
npx expo install <pkg>   # ALWAYS use instead of npm install — picks SDK-compatible versions
npm run ios              # expo run:ios — builds a dev client (needs Xcode + CocoaPods)
npm run android          # expo run:android — needs Android Studio / SDK + Java
npx expo start           # Metro for an already-installed dev client
```

Run `npm test` and `npm run typecheck` before declaring work done.

**Expo Go does not work** for this app (background location, MapLibre, foreground service). Use a development build (`expo-dev-client`), locally or with `npx eas-cli@latest build --profile development`.

`ios/` and `android/` are generated by `npx expo prebuild` (Continuous Native Generation) and gitignored. Never edit them by hand — configure native behaviour in `app.json` / config plugins.

Expo ships breaking changes every SDK. Before touching an Expo API, check the versioned docs for SDK 58 (`https://docs.expo.dev/versions/v58.0.0/`) or the installed types in `node_modules`, not memory. MapLibre RN is v11 (new API: `Map`, `Camera`, `GeoJSONSource`, `Layer` with `paint`/`layout`).

## Architecture

```
expo-location background task (src/engine/tracking.ts)
    → engine.handleLocations → CourseTracker (direction of travel from GPS course)
    → radarStore.radarsNearby (SQLite bbox query)
    → RadarTracker.step (relevance + pass detection)
    → vibrator / voice / notifications
    → engineStore (observable) → React UI
```

| Path | Responsibility |
|---|---|
| `index.ts` | Imports `src/engine/tracking` first so `TaskManager.defineTask` runs at load (required for background delivery) |
| `src/core/` | **Pure, unit-tested logic**: `geo` (haversine, bearing), `radar` (lane filter), `course` (heading), `tracker` (alert selection + pass detection), `vibration` (distance → rhythm), `format`, `refreshPolicy` |
| `src/data/` | `overpass` (OSM fetch + parse), `radarStore` (expo-sqlite cache), `settings` (expo-sqlite kv-store, observable) |
| `src/engine/` | `engine` (orchestrator + `engineStore`), `tracking` (permissions, background task, foreground fallback) |
| `src/alerts/` | `vibrator` (RN `Vibration`), `voice` (expo-speech), `notifications` (expo-notifications) |
| `src/ui/` | `MainScreen`, `AlertCard`, `RadarMap` (MapLibre + OpenFreeMap tiles), `SettingsSheet`, `RadarDetailSheet` |
| `src/lib/createStore.ts` | Tiny `useSyncExternalStore` store shared by background task and UI |
| `src/test/` | Test helpers (not tests) |

**State**: no Redux/Context. `engineStore` and `settingsStore` are module-level observables; components read them with `store.use(selector)`. The background task and UI share the same JS runtime while the app is alive.

## Key behaviour (keep these when changing code)

- **Direction of travel comes from the GPS course**, not the compass (in a pocket the compass is meaningless). Below ~7 km/h, falls back to the bearing between fixes; forgotten after 15 s.
- **Pass detection** (`src/core/tracker.ts`): passed when distance grows > 60 m past the closest approach, or the radar leaves the forward cone after we got within 150 m. Passed radars stay suppressed until we are > alert radius + 150 m away — this fixes the Swift bug where distances kept counting up after passing.
- **Voice announces once** per radar (`isNew`), distance rounded (10 m steps < 100 m, 50 m steps above).
- **Lane filter**: radar must be within ±90° ahead; if it has OSM `direction` tags, one must be within 60° of our course.
- **Stale GPS**: no fix for 30 s → alerts stop (tunnels, waiting at lights).
- **Vibration** (`src/core/vibration.ts`): interval 0.5 s (<50 m), 0.8 s (<150 m), 1.3 s (<300 m), 2 s (<500 m), 3 s beyond. Android pulse length 150–400 ms scales with the intensity slider; iOS system vibration is fixed (~400 ms, full strength).
- **Offline-first**: radars cached in SQLite; refresh from Overpass (100 km radius) when > 7 days old or > 40 km from the last download point. Failed downloads retry at most every 5 min.
- **Battery**: `Accuracy.High` (≈ nearest ten meters), `distanceInterval: 10`. Do not use `BestForNavigation`.
- **Android** runs a location foreground service (persistent "RadarMoto activo" notification) — this is what keeps GPS + vibration alive with the screen off.

## Platform caveats to verify on device

- iOS: whether `Vibration` (system vibrate) fires while the screen is locked; whether expo-speech with `useApplicationAudioSession: false` ducks music and speaks in silent mode.
- Android: TTS does not request audio focus, so music is not ducked yet.
- Both stores review background location strictly: privacy policy and a clear in-app explanation are required. Showing fixed radar locations is illegal in some countries (e.g. France) — launch in Spain first.
- OpenStreetMap data is ODbL: keep the attribution in Settings and the map.
